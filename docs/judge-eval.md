## 2. როგორ გაუშვა

```bash
ANTHROPIC_API_KEY=sk-ant-… JUDGE_EVAL_FIXTURES=/path/to/fixtures npx vitest run tests/judge-eval.test.ts
```

Harness — [`api/tests/judge-eval.test.ts`](../api/tests/judge-eval.test.ts). ორივე ცვლადის
გარეშე **თავისით გამოტოვდება**, ე.ი. ჩვეულებრივი `npm test` არც ფულს ხარჯავს და არც ვარდება.

### Fixture-ის ფორმატი

თითო fixture = ერთი საქაღალდე:

```
fixtures/
  broken-hierarchy/
    frame.png      ← exportAsync PNG (2×)
    nodes.json     ← layer listing, იგივე რასაც plugin აგზავნის
    expect.json    ← { "kind": "broken", "dimensions": ["hierarchy"], "note": "H1 და body ერთი ზომისაა" }
```

`kind`: `broken` (ცხადი პრობლემა) · `good` (კარგი დიზაინი) · `borderline` (სასაზღვრო).

### საჭირო შემადგენლობა (§8.4)

- **5 ცხადი პრობლემით** — თითოეულს `dimensions` მიწერილი
- **5 კარგი დიზაინი** — judge-მა **არაფერი** უნდა თქვას, ან მხოლოდ `nit`
- **3–5 სასაზღვრო**

## 3. გასვლის კრიტერიუმი — რას ამოწმებს harness ავტომატურად

| # | კრიტერიუმი | ზღვარი |
|---|---|---|
| 1 | ცხად პრობლემებზე სწორი `dimension` **და** კონკრეტული `where` | **≥ 80%** |
| 2 | კარგ დიზაინებზე **არცერთი `blocking` finding** | **0** |
| 3 | ყოველ finding-ს ან `what`-ში ან `suggestion`-ში ციფრი/დასახელებული ელემენტი | **0 ბუნდოვანი** |

**კრიტერიუმი 2 ყველაზე მკაცრია და ეს განზრახაა.** blocking finding კარგ დიზაინზე არის
false positive — ზუსტად ის, რასაც პროდუქტი პირდება, რომ არასოდეს გააკეთებს. ერთიც კმარა ჩავარდნისთვის.

⚠️ **რასაც harness ვერ ამოწმებს:** არის თუ არა `suggestion` **სასარგებლო**. ციფრის არსებობა
ბუნდოვანებას ჭრის, ვარგისიანობას არა. §8.4 ითხოვს ხელით გადამოწმებას — **წაიკითხე ყველა
finding და ჰკითხე შენს თავს: დიზაინერი ამას გააკეთებდა?** თუ პასუხი "არა"-ა, eval ჩავარდა,
თუნდაც სამივე რიცხვი მწვანე იყოს.

## 4. Rubric — რა გადაწყვეტილებებია ჩადებული

სრული ტექსტი: [`api/src/services/judgeRubric.ts`](../api/src/services/judgeRubric.ts).

1. **a11y-ს არ იმეორებს.** დეტერმინისტული engine უკვე ზომავს კონტრასტს, target size-ს, line height-ს.
   rubric ცალსახად უკრძალავს მათ ხსენებას — judge სხვა ფენაა: იერარქია, რიტმი, თანმიმდევრობა.
2. **ყოველი finding ციფრს ან პოზიციას ასახელებს.** *"the CTA sits 8px from the card edge while
   every other element uses 16px"*, არა *"spacing could be more consistent"*.
3. **სიჩუმე სწორი პასუხია.** ცარიელი `findings` კარგ ეკრანზე მოსალოდნელია. rubric ცალსახად
   ამბობს: მოგონილი პრობლემა უფრო ძვირია, ვიდრე დუმილი.
4. **ქულა არ ბერდება.** 5 იშვიათია; ერთი `notable`-იც კმარა, რომ 5 აღარ იყოს.

**სქემა enforced-ია სერვერზე** (structured outputs) — მოდელი ვერ დააბრუნებს ფორმას, რომელიც
სქემას არღვევს, ე.ი. route-ის კოდი ნახევრად-verdict-ს ვერასოდეს ნახავს.

| 100/თვე (backend-spec §8.3-ის მაგალითი) | **~$94** | **78%** 🔴 |
| 50/თვე | ~$47 | 39% 🟠 |

**მოდელი განზრახ არ ჩამომიწევია.** Haiku 4.5 ($1/$5) ზარს ~$0.016-მდე ჩამოიყვანს, მაგრამ

`JUDGE_MODEL` და `JUDGE_PRO_MONTHLY` ორივე env-ით იცვლება; **გაუშვი eval ორივე მოდელზე და
შეადარე** (§8.3 სწორედ ამას ითხოვს).
